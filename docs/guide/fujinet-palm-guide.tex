\chapter{Welcome}

A Palm Pilot already has everything it needs to be a network computer except
the network. It has a serial port, a cradle, and HotSync, the one-button
ritual that every Palm owner knows. \textbf{FujiNet} supplies the rest. Put a
Palm in its serial cradle, run the cradle's cable to a FujiNet, and the same
wire now does two jobs:

\begin{itemize}
  \item \textbf{HotSync.} Press the cradle's button and the Palm syncs with
    FujiNet as it once did with Palm Desktop. FujiNet installs whatever apps
    and databases are waiting in its install queue, and backs up the Palm's
    databases to its own storage.
  \item \textbf{FujiBus.} Apps on the Palm talk to FujiNet directly, at 115200
    baud, and through it to the internet: game servers, web pages, TNFS file
    servers, and friends on other Palms.
\end{itemize}

FujiNet notices which of the two is happening by itself. While an app is
talking, it leaves the line alone; when the app goes quiet, it listens now and
then for a Palm's HotSync call.

\section{Two FujiNets, two families of apps}

FujiNet comes in two firmware generations, and this guide covers both:

\begin{description}[font=\sffamily\bfseries,leftmargin=0pt]
  \item[FujiNet Classic] is the long-running \texttt{fujinet-firmware} that
    serves Atari, Apple~II, CoCo, Adam and many other machines. Its Palm
    support lives on the \texttt{palm-demo-fozz} branch. Apps written for it are
    named \textbf{FN} something, like \textsf{FN Test}. \fnbadge
  \item[FujiNet NIO] is the new firmware, \texttt{fujinet-nio}, with devices
    organised as services (network, files, WiFi, HotSync) and a portable C
    client library, \texttt{fujinet-nio-lib}. Apps written for it are named
    \textbf{FI} something, like \textsf{FI Test}. \fibadge
\end{description}

The two families do the same jobs in the same way on the Palm, and look much
alike; the difference is the FujiNet they expect at the other end of the
cable. Each FI app has its own creator code, so a Palm can carry both
families side by side, and the launcher tells them apart by name.

\chapter{Classic and NIO}
\label{ch:diff}

Both firmwares give the Palm the same two services on one cable, HotSync and
FujiBus, and both share the line the same way. They differ in how FujiNet is
configured, where it keeps the install queue, and what the apps speak on the
wire.

\section{Sharing one cable}

A HotSync begins at 9600 baud, while apps talk at 115200. FujiNet cannot hear
a 9600-baud call while it is listening at 115200, so both firmwares do the
same dance:

\begin{enumerate}
  \item When no app has spoken for a minute, FujiNet starts \emph{listening
    windows}: it drops the line to 9600 baud for 1.5~seconds, listens for a
    Palm's HotSync wake-up, then goes back to 115200.
  \item Any app request holds the windows off for another minute, so a running
    app is never interrupted.
  \item Bytes that are not an app request end the wait at once: that is what a
    pressed HotSync button sounds like at 115200.
  \item Once the Palm's wake-up is answered, the sync owns the line until it
    ends, including the switch to a faster rate.
\end{enumerate}

An app request that lands inside a window gets no answer, so every app
resends. On NIO, \texttt{fujinet-nio-lib} also wakes the line with a harmless
request of its own after an idle spell. You will not notice any of this,
except that the first request after a long pause can take a second longer.

\begin{tip}
A Palm running an app cannot HotSync, and a Palm that is HotSyncing is not
running an app. Leave the app (or use its \btn{HotSync} button) before you
press the cradle button.
\end{tip}

\section{Which one do I have?}

Run \textsf{FN Test} and \textsf{FI Test} and tap \btn{Ping}. The one that
says \textsf{FujiNet found!} matches your FujiNet. \textsf{FI Test} also
reports the board NIO is running on, such as \textsf{POSIX + FujiBus over
RS-232} for a computer running NIO.

\chapter{Getting set up}
\label{ch:setup}

\section{Hardware}

\begin{itemize}
  \item A Palm OS handheld (OS 3.1 or later) and its \textbf{serial} HotSync
    cradle or HotSync cable, the kind with a DB-9 plug. USB cradles do not
    work.
  \item A FujiNet with an RS-232 port: the \textbf{FN-RS232} board, or a
    computer running FujiNet-PC or FujiNet NIO with a serial port.
  \item A \textbf{null-modem adapter} between the cradle's DB-9 and the
    FN-RS232's DB-9. Both ends are wired as a computer would be.
\end{itemize}

\begin{warn}
A Palm cradle never raises the RTS/CTS flow-control lines. Build or configure
FujiNet without hardware flow control, or it will wait forever for permission
to send. The classic \texttt{fujinet-rs232-s3-palm} board and NIO's default
\texttt{flow\_control: none} already do.
\end{warn}

\section{FujiNet Classic}

Flash the \texttt{fujinet-rs232-s3-palm} build of the \texttt{palm-demo-fozz}
branch. HotSync is on by default; its settings are in \texttt{fnconfig.ini}
and in the web UI's \textsf{Palm HotSync} panel:

\begin{codebox}
\begin{verbatim}
[HotSync]
enabled=1
user=FujiNet          ; given to a Palm that has never synced
backup=flagged        ; none | flagged | all
netsync_port=14238    ; 0 turns it off
serial_port=bus       ; the cradle shares the RS-232 bus line
\end{verbatim}
\end{codebox}

An SD card is required: the queue is \texttt{/palm/install/}, installed files
move to \texttt{/palm/installed/}, and backups go to
\texttt{/palm/backup/\emph{user}/}. Classic can also fill the Palm's Date Book
from a Google or iCalendar calendar at each sync (\texttt{calendar=GCAL:///}
or \texttt{ICAL://host/feed.ics}).

\section{FujiNet NIO}

HotSync is off by default. Turn it on in \texttt{fujinet.yaml}, or from the
diagnostics console, and restart:

\begin{codebox}
\begin{verbatim}
hotsync:
  enabled: true
  cradle: true         # a Palm cradle shares the FujiBus serial line
  port: 14238          # NetSync TCP port; 0 turns it off
  root: /hotsync       # folder on the persistent filesystem
  user_name: FujiNet   # given to a Palm that has never synced
  backup: flagged      # none | flagged | all
\end{verbatim}
\end{codebox}

\begin{codebox}
\begin{verbatim}
hotsync.set enabled 1
hotsync.set cradle 1
hotsync.save
hotsync.status        # is it listening? what did the last sync do?
\end{verbatim}
\end{codebox}

\section{Installing the apps}

The first app has to arrive by HotSync, so put it in the install queue and
press the cradle button. After that, \textsf{FN HotSync} or \textsf{FI
Config} can queue the rest from the Palm itself. The builds are on the TNFS
server \texttt{fujinet.diller.org}: the FN apps in \texttt{/PALM/}, the FI apps
in \texttt{/NIO/PALM/}.

\begin{description}[font=\sffamily\bfseries,leftmargin=0pt]
  \item[Classic] Copy the \texttt{.prc} to \texttt{/palm/install/} on the SD
    card, or send it over WebDAV:\\
    \texttt{curl -T FN-HotSync.prc http://fujinet.local/dav/palm/install/}
  \item[NIO] Serve the \texttt{.prc} from any computer and fetch it from the
    console:\\
    \texttt{python3 -m http.server 8000} \quad (on the computer)\\
    \texttt{hotsync.fetch http://192.168.1.5:8000/FI-Config.prc} \quad (on NIO)
\end{description}

FujiNet installs the queued files and moves them to \texttt{installed/}, and

\chapter{Palm OS versions}
\label{ch:compat}

Every app runs on Palm OS 3.1 and later. Palm OS 3.3 brought a new Serial
Manager; on 3.1 and 3.2 the apps (and \texttt{fujinet-nio-lib}) fall back to
the older serial library, which does the same job. An app started on Palm OS
3.0 or earlier says \textsf{This app needs Palm OS 3.1 or later} and quits.

FN FujiPet and FI FujiPet draw in 256 colours on a colour Palm running OS 3.5
or later, and in black and white with a grey dither everywhere else. The other
apps are black and white on every Palm.

\chapter{When things go wrong}

\begin{description}[font=\sffamily\bfseries\color{fujired},leftmargin=0pt,style=nextline,itemsep=8pt]
  \item[\textsf{No answer from FujiNet. Is the cradle cabled to it?}]
    The app sent its request several times and heard nothing. Check the
    null-modem adapter, that FujiNet is running, that it was built without
    hardware flow control, and that you are running the right family: FN apps
    with Classic, FI apps with NIO.
  \item[\textsf{This app needs Palm OS 3.1 or later}]
    The Palm runs Palm OS 3.0 or earlier.
  \item[The HotSync button does nothing]
    Quit any FujiNet app first. Check that HotSync is on: on NIO,
    \texttt{hotsync.status} should say \texttt{enabled: 1} and
    \texttt{listening: 1}; on Classic, \texttt{[HotSync] enabled=1} with
    \texttt{serial\_port=bus}. Give it a few seconds: FujiNet listens in
    windows.
  \item[A queued app did not install]
    Look in the queue (\btn{Queue} in FN HotSync or FI Config). On NIO,
    \texttt{hotsync.status} reports \texttt{last\_installed} and
    \texttt{last\_install\_failures}. A copy that FI Config could not finish is
    refused by HotSync; queue it again.
  \item[FujiPet says \textsf{No friend server}]
    Check the server's \textsf{host:port} in \menu{Options > Settings}. A
    computer running NIO on a Mac connects to the IPv6 address for
    \texttt{localhost}, so start the friend server with \texttt{-{}-host \char34\char34}, or
    give its IPv4 address.
  \item[A FujiNet-PC on a Mac drops requests]
    FujiNet-PC builds before the \texttt{[pc]} serial fix left the terminal's
    extended input processing on, which swallows bytes \texttt{0x16} and
    \texttt{0x0F} in a packet. Use a build with the fix.
\end{description}

\chapter{For developers}

\section{Building}

The apps live in \texttt{github.com/dillera/fujinet-palm}: the FN apps on the
\texttt{classic} branch, the FI apps on \texttt{nio}. They build with
prc-tools-remix and PilRC in a Docker image:

\begin{codebox}
\begin{verbatim}
make image    # once: the palmdev toolchain image
make          # every app, apps/*/*.prc
make test     # desktop tests of the shared C code
make traps    # Palm OS calls newer than 3.1, per app
\end{verbatim}
\end{codebox}

On \texttt{nio}, \texttt{make} also builds \texttt{fujinet-nio-lib}'s
\texttt{palm} target from \texttt{../fujinet-nio-workspace}. An FI app sets
\texttt{NIO = 1} in its Makefile; \texttt{fn\_read} never blocks, so poll it
from the event loop, and when a reply is lost ask again at the same offset.

\section{Testing in an emulator}

\texttt{assets/} holds Palm OS ROMs and CloudpilotEmu images with Setup done,
for Palm OS 3.1, 3.3, 3.5 and 4.0, and the patch that gives CloudpilotEmu a
\texttt{-{}-serial} option and scripting commands. \texttt{tools/rig.sh} joins
an emulated Palm's cradle to FujiNet-PC or to FujiNet NIO through a pair of
pseudo-terminals:

\begin{codebox}
\begin{verbatim}
cp assets/images/palm-m100-os3.5.1.img runs/t/palm.img
tools/rig.sh start runs/t runs/t/palm.img nio
tools/rig.sh cmd runs/t install $PWD/apps/FujiNetTest/FujiNetTest.prc
tools/rig.sh cmd runs/t launch 'FI\ Test'
tools/rig.sh cmd runs/t tap 40 147
tools/rig.sh cmd runs/t screenshot ping.png
\end{verbatim}
\end{codebox}

Every screen in this guide was taken that way.
